# Handoff Summary（引き継ぎサマリ）

コンテキスト圧迫時に autocompact へ任せず、必要な文脈を**構造化して新セッションへ引き継ぐ**ためのサマリを生成するスキル。

出力は**チャットのみ**（ファイルは作らない）。ユーザーがこの出力をコピーし、新セッションの冒頭に貼って作業を再開する想定。

## 大原則

- **自己完結**: 前提知識ゼロの新セッションがそのまま再開できるように書く。「さっきの」「例の」「上記の」等の**文脈依存表現を使わない**。ファイル・ブランチ・コマンドは省略せず明記する（パスは絶対パス、コード位置は `file:line`）。
- **記憶でなく事実**: 「現在の状態」は記憶や思い込みで書かず、**実コマンドの出力で確認**してから書く（後述）。
- **正直に**: 完了していないこと・失敗・未検証は、その通りに書く。できていないことを「できた」と書かない。
- **機密を出さない**: `.env` の値・トークン・認証コード・鍵は載せない。必要なら名前だけ書きマスクする。

## 手順

### 1. 現在の状態を実コマンドで確認

記憶に頼らず、最低限これらを実行して結果を「4. 現在の状態」に反映する（リポジトリ作業時）:

```bash
date +%F
git status -sb
git diff --stat
git diff --cached --stat
git log --oneline -5
```

### 2. 会話全体を振り返り、12項目を埋める

下のテンプレートの各項目を、この会話で得た情報から埋める。**該当する情報が無い項目は「なし」と明記**する（項目自体は省略しない＝引き継ぎ漏れの自己チェックになる）。

### 3. チャットに出力

テンプレートをそのまま1つのまとまりとしてチャットに出力する。先頭に「新セッションに貼って続きを指示する」旨の一文を添える。

## 出力テンプレート

```
# 引き継ぎサマリ — <作業テーマ>（<YYYY-MM-DD>）
> 新セッションの冒頭にこの全体を貼り、「この続きから作業して」と指示してください。

## 1. 背景・ゴール
<なぜこの作業をしているか。最終的に達成したいこと。>

## 2. 意思決定とその理由
- 決定: <内容> / 理由: <なぜ> / 却下した代替案: <あれば、なぜ選ばなかったか>

## 3. これまでの作業内容
<実際に行った変更・調査の要約。>

## 4. 現在の状態
- ブランチ: <現在ブランチ / base ブランチ>
- 差分・ステージ状況: <git status / diff --stat の結果>
- 進捗: <どこまで完了 / 何が未完了>

## 5. 次の一手（残タスク）
- [ ] <再開時に最初にやること>
- [ ] <以降の残タスク>

## 6. 未解決の問題・ブロッカー・保留事項
<詰まっている点、判断保留中の事項。なければ「なし」。>

## 7. 重要ファイルと場所
- `path/to/file.ext:line` — <何があるか・なぜ重要か>

## 8. 落とし穴・前提・制約
<ハマった点、環境固有の注意（例: ダミー AWS creds 必須、CI=true でテスト）、踏むと困る罠。>

## 9. このセッション特有の指示・合意
<CLAUDE.md に無い、その場でのユーザー指示・取り決め（例: 「コミットするな」「日本語で」）。>

## 10. 検証方法
- `<コマンド>` — <何を確認するか>

## 11. 試したがダメだった方法（dead ends）
<試して効果が無かった/間違っていたアプローチ。新セッションが同じ無駄を繰り返さないように。なければ「なし」。>

## 12. 参照リソース
- PR #<番号> / Issue / ドキュメント / URL（なければ「なし」）
```
