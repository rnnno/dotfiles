# checkpoint

長いランの途中で、計画とのズレ（ドリフト）を補正するスキル。

対象は会話の文脈から読み取る（ユーザーが計画ファイルのパスを示していればそれを使う）。

`handoff-summary` スキルとは目的が異なる: `handoff-summary` は**別セッションへの引き継ぎ用**、このスキルは**同一セッション内**で自分の認識を計画ファイルに再同期させるためのもの。

## 手順

1. **アクティブな計画ファイルを特定し、全文を再読する。**
   パスが示されていればそのパス。無ければこの会話で既に開いた計画ファイルを使う。それも無ければ `~/.claude/plans/` を更新時刻順に提示してユーザーに確認する（`~/.claude/plans/` のファイルにセッションを特定する情報は無いため、更新時刻が最新なだけのファイルを黙って選ばない。別プロジェクトの計画を棚卸しする事故になる）。計画ファイルが存在しない場合はその旨を明示し、この会話で承認された計画（plan mode の出力・着手前に提示したスコープ）を対象にする。
   会話の要約や自分の記憶ではなく、**ファイルの実体**を読む。

2. **サブタスクごとに証拠を確認する。**
   「完了した」と認識しているサブタスクそれぞれについて、この会話内にある具体的な根拠（コマンド出力、diff、テスト結果など）を探す。
   - 根拠があれば: その根拠を挙げて「完了（証拠あり）」とする。
   - 根拠が無ければ: 以前「完了」と述べていても**「未検証」に降格する**。楽観的な自己申告をそのまま引き継がない。

3. **当初ゴールとのドリフトを検査する。**
   実際の差分を計画と突き合わせる。`git status -sb` と `git diff --stat`（必要なら `git diff --cached --stat`）を実行し、変更されているファイルと計画に書かれた対象ファイルを照合する。計画に無いファイルが変更されていれば列挙し、計画にあるのに触られていないファイルも列挙する。リポジトリ外の作業なら、計画の各サブタスクと会話内の実施記録を1対1で照合する。「ドリフトはありません」を記憶で答えない。

4. **状態を報告する。**
   サブタスク／状態（完了・証拠あり｜未検証｜未着手）／次にすべきこと、の一覧を簡潔に提示する。ドリフトがあれば明示する。
