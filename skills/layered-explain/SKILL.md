# layered-explain

システムや機能の仕組みを、抽象度の高い順に3層で説明する。各層の後で止まり、次の層へ進むか、別の要素を掘り下げるかをユーザーが決める。

対象は会話から読み取る。範囲が曖昧なとき（例: 「認証」がログインだけか、トークン更新まで含むか）は、層1に入る前に一度だけ確認する。

## 手順

1. **調べてから書く。**
   層1を書く前に、対象のコードや設定を読んで構成要素と流れを把握する。層1は短いが、根拠なしに書かない。

2. **層1: 抽象的な概要（5行以内）。**
   構成要素とそれぞれの目的、要素間の関係だけを書く。ファイルパス・関数名・具体例・反論は入れない。
   書き終えたら、層2（データの流れ）に進むか、特定の要素を先に掘り下げるかを聞いて止まる。

3. **層2: データの流れ。**
   入口から出口まで、データや制御がどう渡るかを順に書く。各ステップにリポジトリ相対のフルパスと行番号を付ける（例: `apps/server/src/guards/ip.guard.ts:69`）。
   書き終えたら、層3に進むかを聞いて止まる。

4. **層3: エッジケースと詳細。**
   エラー時の挙動、分岐条件、環境ごとの差、既知の制約など、層2で省いたものを書く。

## 全層共通

- 事実のみを書く。コードや設定で直接確認できず推測したものには [推測] を付ける。
- 改善提案や推奨は書かない。求められた場合だけ、別のセクションに分けて書く。
- ユーザーが途中で別の要素の掘り下げを求めたら、そちらに従う。層の順番を守るために押し戻さない。
