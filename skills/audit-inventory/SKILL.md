# audit-inventory

削除対象・棚卸し・影響範囲などの一覧を、作成者とは独立したエージェントに照合させ、食い違いを直してからユーザーに見せる。作成者自身の見直しでは、作成時と同じ見落としを繰り返しやすいため。

## 手順

1. **照合先を決める。**
   一覧の根拠になりうる情報源を選ぶ。ユーザーが照合先を指定していればそれに従う。典型例:
   - IaC（terraform など）: 照合前に `git fetch` し、最新の状態を読む
   - コード上の参照（呼び出し元・環境変数・設定）
   - 実際の利用状況（New Relic の直近30日のトラフィックなど）
   - 稼働中のリソース（読み取り専用の AWS CLI など）

   使える情報源が1種類しかない場合は、その旨を最終報告に明記する。

2. **監査エージェントを起動する。**
   general-purpose サブエージェントに以下だけを渡す。一覧を作った経緯や「これで網羅しているはず」といった説明は渡さない（作成時の思い込みを引き継がせないため）。

   ```
   監査対象の一覧: <一覧そのもの>
   一覧の目的: <何のための一覧か（例: mart-api 廃止に伴い削除するリソース）>
   照合先と手段: <情報源ごとの場所・コマンド・クエリ>
   制約: 読み取り専用の操作のみ。クラウドへの照会は読み取り専用の権限で行う。
   報告形式: 食い違いごとに「種別（漏れ / 過剰 / 誤り）・対象・根拠（file:line、コマンド出力、クエリ結果）」
   ```

3. **一覧を修正する。**
   報告された食い違いを1件ずつ根拠と照らして確認し、妥当なものを一覧に反映する。妥当でないと判断したものは、理由を添えて記録する。

4. **提示する。**
   修正後の一覧と、監査で見つかった食い違い（反映したもの、反映しなかったものとその理由）を合わせて示す。照合できなかった項目は、照合できなかったことを明記する。
